# Хранитель Байкала

Мини-приложение отеля для MAX с фотографиями, каталогом номеров, картой, расчётом проживания и связью с ресепшеном

## Размещение на российском хостинге

Для версии с сервером можно импортировать этот репозиторий в [Timeweb Cloud App Platform](https://timeweb.cloud/docs/apps/how-it-works) как приложение с Dockerfile, выбрать российский регион и указать порт контейнера 3000. На другом сервере с Docker подходит тот же Dockerfile

1. Разверните ветку `main` и получите публичный HTTPS-адрес приложения
2. Укажите его в переменной `SITE_ORIGIN` для ссылок и фотографий в ответах чат-бота
3. Проверьте главную страницу и маршрут `/healthz` с российского интернета
4. В [кабинете MAX](https://business.max.ru/self/chat-bots) откройте настройки существующего бота «Хранитель Байкала» и замените ссылку мини-приложения новым проверенным HTTPS-адресом

### Проверка номеров в ECVI

Задайте `ECVI_PMS_BASE_URL` (HTTPS-адрес до `/pmsapi` от ECVI), `ECVI_HOTEL_ID` и `ECVI_HOTEL_TOKEN` в переменных сервера. Производственный адрес задаётся явно. Если у отеля несколько сегментов, укажите `ECVI_SEGMENT_ID`. Если названия категорий в ECVI отличаются от каталога, задайте `ECVI_ROOM_TYPE_IDS` как JSON с сопоставлением, например `{"family":"101","comfort":"102"}`. Ключи каталога — `family`, `family-comfort`, `comfort`, `suite`, `presidential`

При заданных `ECVI_TARIFF_ID` и `ECVI_DIET_ID` форма может показать цену ECVI за проживание 1–3 взрослых, если есть однозначное предложение по этому тарифу. Для допмест используется предварительный расчёт. Форма проверяет даты через документированный `GET /avaliable_resourcetypes`, а бронирование подтверждает администратор. Паспортные данные не запрашиваются

### Стыковка с iiko

Интерфейс `/iikoapi` в переданном Swagger предназначен для выгрузки проживающих гостей и начислений на гостевой счёт. Брони столиков он не принимает. Для операторской проверки связи задайте `IIKO_BASE_URL` и `IIKO_HOTEL_TOKEN` на сервере и выполните `npm run iiko:check`. Команда печатает статус доступа, содержимое ответов остаётся на сервере. В мини-приложении бронирование столика открывает звонок в гастродом

Для автоматического меню в чате задайте `MAX_BOT_TOKEN` и новый `MAX_WEBHOOK_SECRET`, затем зарегистрируйте `<HTTPS-адрес>/max/webhook` по [инструкции MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions/). Если сервер не доверяет сертификатам API MAX, подключите доверенную цепочку сертификатов Минцифры к Node через `NODE_EXTRA_CA_CERTS`. Настройку источника событий согласуйте с работающим обработчиком бота: MAX не поддерживает Long Polling при активном вебхуке

`MAX_ADMIN_PHONE` и `MAX_ADMIN_CHAT_URL` — необязательные настройки контакта для гостей. Используйте рабочие контактные данные, которые можно публиковать. Файл `.env.example` содержит только имена переменных

## Статическое превью

В GitHub Settings → Pages выберите **GitHub Actions**. Workflow публикует папку `dist`. Контакты ресепшена задаются переменными Actions `BAIKAL_ADMIN_PHONE` и `BAIKAL_ADMIN_CHAT_URL`

Кнопки связи открывают чат администратора в MAX. Простые вопросы об отеле обрабатываются внутри мини-приложения, остальные переводят гостя в MAX

GitHub Pages рассчитывает предварительную стоимость. Чтобы сохранить текущую ссылку в MAX и подключить проверку наличия, задайте в переменной Actions `BAIKAL_API_ORIGIN` HTTPS-origin сервера, а на сервере в `MINI_APP_ORIGIN` — `https://1dambek1.github.io`. Браузер получает только адрес проверки. Токены ECVI и iiko хранятся на сервере

## Локальный запуск

Требуется Node.js 22 или новее

```sh
npm run build
npm start
```

Откройте `http://localhost:3000`
