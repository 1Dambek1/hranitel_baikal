# Хранитель Байкала

Мини-приложение отеля для MAX с фотографиями, каталогом номеров, картой, расчётом проживания и связью с ресепшеном

## Размещение на российском хостинге

Для версии с сервером можно импортировать этот репозиторий в [Timeweb Cloud App Platform](https://timeweb.cloud/docs/apps/how-it-works) как приложение с Dockerfile, выбрать российский регион и указать порт контейнера 3000. На другом сервере с Docker подходит тот же Dockerfile

1. Разверните ветку `main` и получите публичный HTTPS-адрес приложения
2. Укажите его в переменной `SITE_ORIGIN` для ссылок и фотографий в ответах чат-бота
3. Проверьте главную страницу и маршрут `/healthz` с российского интернета
4. В [кабинете MAX](https://business.max.ru/self/chat-bots) откройте настройки существующего бота «Хранитель Байкала» и замените ссылку мини-приложения новым проверенным HTTPS-адресом

### Проверка номеров в ECVI

Задайте `ECVI_PMS_BASE_URL` (HTTPS-адрес до `/pmsapi` от ECVI) и `ECVI_HOTEL_ID` в переменных сервера. Для авторизации задайте `ECVI_HOTEL_TOKEN` или пару `ECVI_PMS_USERNAME` и `ECVI_PMS_PASSWORD`, которую ECVI выдала для PMS API. При наличии обоих вариантов используется токен. Адрес `https://demo2.ecvi.ru/pmsapi` указан для тестового сервера. Для данных отеля нужен выданный ему доступ и адрес соответствующего сервера

Если у отеля несколько сегментов, укажите `ECVI_SEGMENT_ID`. Если названия категорий в ECVI отличаются от каталога, задайте `ECVI_ROOM_TYPE_IDS` как JSON с сопоставлением, например `{"family":"101","comfort":"102"}`. Ключи каталога — `family`, `family-comfort`, `comfort`, `suite`, `presidential`

При заданных `ECVI_TARIFF_ID` и `ECVI_DIET_ID` форма может показать цену ECVI за проживание 1–3 взрослых, если есть однозначное предложение по этому тарифу. Для допмест используется предварительный расчёт. Форма проверяет даты по выбранной или сразу по всем категориям через `GET /avaliable_resourcetypes`. Без настроенного модуля онлайн-бронирования бронь подтверждает администратор

Команда `npm run ecvi:check` проверяет сегменты, категории, наличие по категориям и по отдельным номерам, а также список допуслуг. По умолчанию проверяется одна ночь с завтрашнего дня по времени Листвянки. Для других дат передайте заезд и выезд в формате `YYYY-MM-DD`, например `npm run ecvi:check -- 2027-05-01 2027-05-03`. Отчёт содержит коды ответов, количество записей и сопоставление категорий. Данные гостей и доступы в отчёт не выводятся

### EXT PMS API для бронирования по категориям

[EXT PMS API](https://demo2.ecvi.ru/swagger/extpmsapi/index.html) поддерживает проверку наличия и цен по категориям. Для этого задайте `ECVI_EXT_PMS_BASE_URL` (на демо — `https://demo2.ecvi.ru/extpmsapi/`), `ECVI_HOTEL_ID`, `ECVI_SEGMENT_ID`, `ECVI_ROOM_TYPE_IDS` и доступ к EXT PMS через `ECVI_EXT_PMS_HOTEL_TOKEN` или пару `ECVI_EXT_PMS_USERNAME` и `ECVI_EXT_PMS_PASSWORD`. При двух настроенных API проверка наличия использует обычный PMS. Для календаря с номерами на дверях нужен обычный PMS с `GET /avaliable_resources`

Команда `npm run ecvi:check -- --external` проверяет чтение категорий и показывает ID из возвращённых предложений. Создание броней, передача платежей и подтверждение статусов этой командой не выполняются. Для оплаты через собственную интеграцию нужен отдельный платёжный сервис. ECVI может автоматически отменять неоплаченные брони через заданное в отеле количество часов

### Карточки номеров и календарь

Категории и фотографии конкретных номеров хранятся в `dist/room-directory.json`. Ключ — номер на двери, `roomId` берётся из каталога, `photos` содержит до трёх имён файлов WebP из `dist/photos`. Пример записи для номера 1 — `{"1":{"roomId":"suite","photos":["room-1-a.webp","room-1-b.webp","room-1-c.webp"]}}`

Для дат конкретного номера задайте на сервере `ECVI_ROOM_RESOURCE_IDS` как JSON, например `{"1":"идентификатор-ресурса-ECVI"}`. Календарь запрашивает наличие по ночам через `GET /avaliable_resources` и возвращает только статусы дат. Серые даты означают, что подтверждённых данных нет. Календарь не показывает гостевые данные или идентификаторы ресурсов

Временное удержание и выдачу платёжного QR для заявки сейчас выполняет администратор. Автоматическое удержание требует согласованного срока и правила освобождения номера при просрочке. Считывание Цифрового ID в предоставленном сценарии ECVI выполняется при заселении через карточку гостя

### Модуль бронирования на сайте

В кабинете ECVI откройте «Администрирование → Отель → Настройка модуля бронирования». Для страницы `dist/booking.html` выберите тип «Основная страница бронирования», ID блока `ecvi-booking` и HTTPS. Для текущей публикации адрес страницы — `https://1dambek1.github.io/hranitel_baikal/booking.html`. Нажмите «Сгенерировать», затем «Сохранить» и вставьте полученный код перед `</body>` в `dist/booking.html`

Если в кабинете ещё нет активного веб-канала бронирования, его включает поддержка ECVI. При необходимости стартовый виджет генерируется отдельным кодом с адресом этой страницы. После проверки формы задайте `BAIKAL_HOTEL_BOOKING_URL` с адресом страницы, чтобы в MAX появилась кнопка «Забронировать онлайн». Подробности в [документации модуля бронирования](https://help.ecvi.ru/books/baza-znanii-ecvi/page/modul-bronirovaniya-na-saite-otelya)

### Стыковка с iiko

Интерфейс `/iikoapi` в переданном Swagger предназначен для выгрузки проживающих гостей и начислений на гостевой счёт. Брони столиков он не принимает. Для операторской проверки связи задайте `IIKO_BASE_URL` и `IIKO_HOTEL_TOKEN` на сервере и выполните `npm run iiko:check`. Команда печатает статус доступа, содержимое ответов остаётся на сервере. В мини-приложении доступен звонок в гастродом. Кнопка онлайн-резерва появится при задании `BAIKAL_GASTRO_BOOKING_URL` со ссылкой на рабочую гостевую форму ресторана

Для автоматического меню в чате задайте `MAX_BOT_TOKEN` и новый `MAX_WEBHOOK_SECRET`, затем зарегистрируйте `<HTTPS-адрес>/max/webhook` по [инструкции MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions/). Если сервер не доверяет сертификатам API MAX, подключите доверенную цепочку сертификатов Минцифры к Node через `NODE_EXTRA_CA_CERTS`. Настройку источника событий согласуйте с работающим обработчиком бота: MAX не поддерживает Long Polling при активном вебхуке

`MAX_ADMIN_PHONE` и `MAX_ADMIN_CHAT_URL` — необязательные настройки контакта для гостей. Используйте рабочие контактные данные, которые можно публиковать. Файл `.env.example` содержит только имена переменных

## Статическое превью

В GitHub Settings → Pages выберите **GitHub Actions**. Workflow публикует папку `dist`. Контакты ресепшена задаются переменными Actions `BAIKAL_ADMIN_PHONE` и `BAIKAL_ADMIN_CHAT_URL`

Кнопки связи открывают чат администратора в MAX. В разделе «Вопросы» доступны готовые ответы и прямая кнопка «Написать нам в MAX»

GitHub Pages рассчитывает предварительную стоимость. Чтобы сохранить текущую ссылку в MAX и подключить проверку наличия, задайте в переменной Actions `BAIKAL_API_ORIGIN` HTTPS-origin сервера, а на сервере в `MINI_APP_ORIGIN` — `https://1dambek1.github.io`. Публичные ссылки на формы бронирования для Pages задаются через Actions `BAIKAL_HOTEL_BOOKING_URL` и `BAIKAL_GASTRO_BOOKING_URL`. Токены ECVI и iiko хранятся на сервере

## Локальный запуск

Требуется Node.js 22 или новее

```sh
npm run build
npm start
```

Откройте `http://localhost:3000`
